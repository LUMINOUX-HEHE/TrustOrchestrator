# 02 — L0 Trust Engine: Detailed Specification

L0 is the per-org trust engine that ships in this repository
(`trustorchestrator`). It is the substrate of the entire program: a
signed timeline, a verifiable RFC 9162 append-only log, threshold-anchor
cryptography, cross-org key import with scoped reachability, an event
model for detection, and proactive-key plumbing. Everything above (L1–L5)
consumes L0's signed observations; nothing above L0 is needed for L0 to
be correct. This document is the normative L0 design: modules, invariants
(with proofs), API surface, threat model, and the honest-limits section
that upper layers must map to.

---

## 1. Design goals and non-goals

**Goals.**
- G1. Any verifier, given the right keys, can *audit* an org's entire
  security-relevant history offline.
- G2. No single point of compromise: even a full gateway compromise
  leaves the council anchor, witnesses, and the log as external truth.
- G3. Detection of compromise, key loss, or history rewrite is fast,
  public (via witnesses), and auditable.
- G4. Zero third-party runtime dependencies; pure-Go, stdlib-only
  cryptographic core.
- G5. Demo-grade performance that reproduces the numbers in this file.

**Non-goals.** Hardware enclaves; real multi-host networking; full
asynchronous consensus; private transparency (that is L2); anything that
requires trusting another org.

## 2. Cryptographic core (module-by-module)

### 2.1 `crypto.go` — key material

| Key | Purpose | Generated by | Exposure |
|---|---|---|---|
| `bootstrap.key` | root of trust, Ed25519 | `bootstrap` cmd | stored with the bootstrap device |
| `node.key` | device identity for API calls | `bootstrap` cmd | sealed per host |
| `gateway.key` | gateway identity, timeline, signatures | `bootstrap` cmd | sealed per host |
| `pqkey` (Kyber) | PQ-protected key record | `bootstrap --pq` | sealed, signed together with Ed25519 (`pq.go` dual-signature) |

Dual-signature envelope (`pq.go`): a record is `{pub1, sig1, pub2, sig2,
kid}` where `sig1` = Ed25519, `sig2` = Kyber; verification requires both.
This is the PQ-transition seam: roll the classical key without breaking
anything.

### 2.2 `timeline.go` — the signed append-only log

**Data structure.** `Timeline` = an ordered sequence of `TrustEvent`s.
`TrustEvent` = `{ID, Parent, Ts, Type, Summary, Sigs, Msg, Origin, Ack}`.
`Sigs` contains one signature per signer (owner and optionally a council
member); `Ack` marks cross-org-acknowledged events. `Parent` forms a
hash chain: `Parent = SHA-256(prev event canonical bytes)`.

**Append rules.**
- A1. `Ts` is non-decreasing.
- A2. `Parent` is the hash of the last event (immutability).
- A3. `Sigs` covers the canonical event bytes (sorted keys, exact field
  order, no whitespace).
- A4. Events can be appended after a full restart (durable append:
  fsync'd; journaling; reply-logs replay on boot).

**Event types (existing):** `APPROVED_IMPORT`, `REJECTED_IMPORT`,
`KEY_IN_USE`, `KEY_END`, `KEY_REVOKED`, `ALARM`, `COMPROMISE_DETECTED`,
`INFO`, `WARNING`, `CRITICAL`, `ROTATION`, `COUNCIL_CREATED`,
`COUNCIL_MEMBER_ADDED`, `COUNCIL_MEMBER_REMOVED`.

**Watchdogs.** Internal detectors that emit events: threshold count of
detection sensors, missing ACK timeout, foreign-signature detection,
council-certificate expiry, import storm (burst detection), key-age
policy. All watchdogs are *event producers only* — they never block.

### 2.3 `ctlog.go` — RFC 9162 transparency log

**Leaf.** `LeafHash(entry) = SHA-256(0x00 ‖ entry)` where `entry =
SHA-256(event canonical bytes)` — the leaf commits to the timeline
without revealing event contents (privacy seam for L2).

**Node.** `nodeHash(l, r) = SHA-256(0x01 ‖ l ‖ r)`.

**Tree.** `MerkleLog` stores: `Store` (leaf hashes), `Size`, `Root`
(computed via `mth`), `path` (inclusion proof cache), `consPath`
(consistency proof cache). `Append` stores the leaf hash and recomputes
the root. The tree is rebuilt from the event log O(n) per request —
documented simplification (`// ponytail: rebuild per request; switch to
persistent tree when profiles demand`) — n is tiny in practice (≤ 10⁵
events).

**Proofs (RFC 9162 semantics, both normative):**
- `InclusionProof(idx, size) → (root, proof)`: the minimal node set
  proving `leaf(idx) ∈ tree(size)`, computed by walking the leaf path
  (`splitPoint` decomposition). Verifier: `VerifyInclusion(leaf, idx,
  size, proof)` (§2.1.3.2 of RFC 9162). Rejects `idx ≥ size`.
- `ConsistencyProof(sz1, sz2) → (proof)`: proves `tree(sz1)` is a
  prefix of `tree(sz2)` (§2.1.4.2). Note RFC 9162's asymmetry: when
  `sz1` is an exact power of two, the old root is *prepended* to the
  proof, so the verifier includes it as an implicit first proof node.
- Both verifiers are standalone functions (no MerkleLog needed) — this
  is the exact seam L5 will machine-check first.

**STH.** `STH = {tree_size, timestamp, root}` signed with the log key
(Ed25519): `SignSTH`. Verification: `STH.Verify(pub)`.

**Gossip.** `GossipNode{pub, trusted *SignedTreeHead, alarm bool}`.
`Observe(sth, proof, proofFrom)`:
- TOFU: accept any first valid STH when `trusted == nil` or
  `trusted.TreeSize == 0`.
- Else: require `VerifyConsistency(trusted, sth)`.
- Same size, different root ⇒ split-brain alarm; non-extending history
  (proof-from mismatch) ⇒ inconsistency alarm.
- Every acceptance/refusal is a signed `ALERT` observation (seam §2.1).

### 2.4 `council.go` — threshold trust anchor

`Council` = `{Name, Cert *x509.Certificate, Members, MembersByID,
MemberIDs, Threshold, Height, Pending}`. Certificates are
self-signed, chained by `Parent` from the bootstrap cert, and include
`Scopes` (per-member action scopes). Every certificate is a timeline
event (`COUNCIL_CREATED`, `COUNCIL_MEMBER_ADDED`, …) — the council's
entire history is on the log.

Quorum rule: **all actions require ≥ Threshold confirmations**, where
Threshold = ⅔ majority of current members, unless the action's scope
requires unanimity (e.g., revocation of the root membership). Actions:
`ROTATE_KEY`, `CREATE_SESSION`, `UPDATE_POLICY`, `SET_MANUAL_BYPASS`,
`SCP` (signing ceremony payloads), `IMPORT`.

### 2.5 `graph.go` — cross-org key import with scoped reachability

- Imported keys live in `Keys` with `Importer`, `TrustedImporter`,
  `Scopes`, `StartTime`, `EndTime`.
- `ReachableBy` / `ReachabilityGraph`: BFS over import edges from a
  starting set, bounded by `MaxReach` (default 4 hops) and scope filters.
  This answers "which orgs' keys could have signed this artifact?" —
  the blast-radius primitive that L3 consumes.
- Imports are events (`APPROVED_IMPORT`); revocation is an event
  (`KEY_REVOKED`); both are signed, so the whole import history is
  auditable — the raw material for the trust-edge seam (§2.2 of `01`).

## 3. API surface (normative)

All endpoints: JSON, bearer-token auth (`gateway.key`), role-filtered.

### 3.1 Identity and trust

| Endpoint | Purpose |
|---|---|
| `GET /v1/cert` | gateway certificate chain |
| `GET /v1/keys` | key inventory with scope + reachability info |
| `POST /v1/keys` | rotate a key (council-required) |
| `GET /v1/policy` / `POST /v1/policy` | policy read/update (council-required) |
| `POST /v1/council/import` | import a foreign key with scopes |
| `GET /v1/council` | council info (members, threshold, certs) |
| `POST /v1/council/members` | add/remove member (council-required) |

### 3.2 Transparency (RFC 9162)

| Endpoint | Purpose |
|---|---|
| `GET /v1/orgs/{org}/ct/sth` | signed STH |
| `GET /v1/orgs/{org}/ct/proof?index=&size=` | inclusion proof (+`leaf_hash_hex`, `root_hex`) |
| `GET /v1/orgs/{org}/ct/proof?from=&to=` | consistency proof (`old_root_hex`, `new_root_hex`) |
| `POST /v1/orgs/{org}/ct/gossip` | push an STH + proof; returns `accepted`, `alarm` |
| `GET /v1/orgs/{org}/timeline?start=&end=&type=` | signed events |

### 3.3 Operations

| Endpoint | Purpose |
|---|---|
| `GET /v1/health` | liveness + log size |
| `GET /v1/report` | compliance & audit report (JSON) |
| `GET /v1/export` | signed bundle for offline audit |
| `POST /v1/witnesses` | register an external witness URL |

Roles: `viewer` (read), `operator` (read+ops), `admin` (everything +
council actions).

## 4. Invariants and proofs

These are the properties L5 will machine-check. Stated here with
informal proof sketches (the `demo()`/`__main__` checks in `cmd/`
enforce the reachable ones today).

- **I1 (Timeline immutability).** Appended events form a hash chain;
  rewriting event *i* invalidates all successors (`Parent` recompute
  fails). Proof: SHA-256 collision resistance + A2.
- **I2 (Timeline ordering).** `Ts` non-decreasing. Proof: A1 + enforced
  in append.
- **I3 (Log append-only).** MerkleLog sizes are non-decreasing and
  `tree(s)` is a prefix of `tree(s')` for `s' ≥ s` (RFC 9162 §2.1.4.2
  verifies this externally).
- **I4 (STH binding).** A valid STH signature binds `tree_size`,
  `timestamp`, `root`: `STH.Verify` recomputes the exact signed bytes.
- **I5 (Detection completeness for single-actor compromise).** If an
  attacker replaces gateway keys (not the council), the council can
  revoke them (scope + threshold) and every such action is on the log.
  Proof: council key compromise requires ≥ Threshold members (§2.4);
  scope model bounds actions to authorized sets.
- **I6 (Cross-org accountability).** Every imported key's arrival and
  removal is an event; reachability results are functions of the event
  log only. Proof: graph built from `Keys` which is derived from events.

## 5. Threat model (normative)

| # | Attacker | Capabilities | L0 defense | Residual risk (mapped layer) |
|---|---|---|---|---|
| T1 | Rogue operator | gateway files, API tokens | sealed keys, journaling, council for privileged ops | key in memory (L4 discipline score) |
| T2 | Network attacker | reads/writes traffic | signatures everywhere; bearer tokens; mTLS optional | — |
| T3 | Key thief (single) | one org key | council quorum for rotation; `KEY_REVOKED` on log | lateral move to other orgs (L3 correlation) |
| T4 | Key thief (threshold) | ≥ Threshold council members | detection event + alarm (cannot be silent) | split-brain (L2 witnesses) |
| T5 | History rewriter | gateway + storage | log is append-only; witnesses hold old STHs (L2) | none if ≥1 witness outside attacker's control |
| T6 | Import attacker | forges foreign certs | scope model, `Scopes` check on every use | scope misconfiguration (L5 check) |

## 6. Honest limits (normative — the seam L1–L4 must cover)

| Limit | Why it exists | Upper layer |
|---|---|---|
| L1a. Detection is per-org and silent-capable | no external party polls by default | L2 witnesses, L3 correlation |
| L1b. No cross-org decision authority | L0 only implements org-local policy | L1 shared policy |
| L1c. No private queries over other orgs' logs | L0 logs are public-by-design | L2 ZK claims |
| L1d. No reputation / incentive | L0 is a single-org engine | L4 |
| L1e. No machine-checked proofs of the above | L0's invariants are asserted, not proven | L5 |

## 8. The seam (normative, consumed by L1–L5)

- **Signed observations** (`STH`, `ALERT`, `ROTATION`, `RECOVERY`,
  `SCORE`) per `01 §2.1` — a small extension of the existing event
  model.
- **Key fingerprint registry** (`01 §2.2`) — index over signed
  fingerprints; predicates authorized via L2.
- **Trust-edge metadata** (`01 §2.3`) — signed export of `graph.go`
  reachability edges.
